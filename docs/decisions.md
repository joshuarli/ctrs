# Decisions

Binding decisions made during execution that a later slice depends on. Campaign-level decisions live in `docs/campaign-headless-kiri.md` (Decisions section, owner/prescribed/delegated); this file records the slice-level ones with dates. Append only; never rewrite history here.

## 2026-11-13

- **Import method (CTRS-01, P1):** file-tree copy at the pin, no `.github/`, no `__pycache__`; byte-identical to upstream otherwise. Recorded in `docs/upstream.md`.
- **rustix 1.1.5 → 1.1.6 (CTRS-02, b96e7e3):** RUSTSEC-2026-0486 unsoundness in zero-length xattr queries, reachable via `kiri-image` tar unpack. Other audit findings (`glib`, `proc-macro-error`) delete with the UI in CTRS-07.
- **Musl cross-link env (CTRS-03):** the user's global cargo config injects `-B/usr/local/libexec/mold` into every target and no mold exists on this host (nor the path). musl builds must run with `CARGO_ENCODED_RUSTFLAGS=""`, which overrides all config rustflags; project `.cargo/config.toml` keeps upstream's `rust-lld` linker choice and documents the quirk. Do not "fix" by editing the global config.
- **Guest kernel build via OrbStack (CTRS-03, Decision O2):** only `cargo xtask kernel|disk` (debian:trixie, `kiri-kbuild` volumes). June 2026 owner answer: no Linux verification this run; OrbStack used solely for the kernel/disk build.

- **cargo prunes the lock on demand (CTRS-07, D7):** after deleting the UI/GTK/Share dependency declarations, `cargo check --workspace` removed 85+ packages from `Cargo.lock` automatically (gtk/glib/webkit2gtk/javascriptcore-rs/objc2-app-kit/objc2-web-kit/objc2-core-text/rcgen/rustls/webpki-roots and their unique transitive deps). Additive-only churn; no unrelated updates. `cargo audit` reports zero findings afterwards.
- **Kiri Share deleted end-to-end (CTRS-07):** `share.rs`, `kiri-share-proto/`, `build.rs`+`build_share_key.rs` (the `KIRI_SHARE_BUILD_KEY` compile-time attestation), `/kiri/k8s/forward` routes, `appwatch.rs` (own-app watcher), `update.rs` (auto-updater), `setup.rs` (docker-context creation, LaunchAgent, `/etc/resolver` install) and every command they served (`kiri k8s|machine|usb|import|share|setup|update|bench|boot`). The engine never creates a docker context; the only remaining socket-adjacent context is `kiri`, made on demand by the kept BuildKit builder path (`builds.rs` ensures it for `docker buildx`).
- **Container domains deleted (CTRS-07):** `*.kiri.local`/`*.kiri.localhost` routers, the TLS CA (`daemon/tls.rs`, `rcgen`), the `~/Kiri` NFS/Finder mount (`daemon/nfs.rs`), `/etc/resolver` install and `KIRI_NO_FINDER` are gone. `dns.rs` keeps only the guest→Mac resolver relay (`serve_relay`); its `SUFFIX` skip now hardcodes `kiri.local` (documented in code). Domains shown for containers are gone from `engine.rs` (`route`, `DOMAIN_LABEL`) and `docker events`-adjacent surfaces unchanged.
- **USB passthrough deleted end-to-end (CTRS-07):** host `usb*.rs`, `daemon/usb.rs`, `kiri-init`'s vhci attach path and the `UsbNodes` wire messages, the `/kiri/usb*` API routes, `tests/usb.sh`, and the guest kernel's USB/vhci/evdev/HID block (hence the kernel rebuild; prior hashes in `docs/baseline.md` are stale). SSH-agent forwarding stays (headless-relevant).
- **FS-view deleted end-to-end (CTRS-07):** `FsStat`/`FsList`/`FsRead`/`FsData` wire messages, `vmlink.rs` FS calls, `engine.fs_stat/fs_list/fs_read`, agent arms in `kiri-init`, and `fsview.rs` reduced to `openat2(RESOLVE_IN_ROOT)` resolution for `docker cp`. The finder/file-browser backend had no headless consumer.
- **Crash upload / Kiri Cloud deleted (CTRS-07):** `diag report --send`, `spawn_crash_sender`, crash-claim/upload machinery; `kiri diag report` writes a local file only. `without_names` (name scrubbing for uploads) died with it; its test was removed. The `KIRI_STATE_DIR` test isolation from CTRS-04 stands.
- **grype scanning deleted (CTRS-07):** `scan.rs`, `tools.rs` (Lite CLI downloader), `cli_pins.rs` (pinned docker/compose/buildx/grype for the Mac bundles — the headless fork bundles no CLI). The `X-Kiri-*` routes they served (`/kiri/images/scan*`, `layers`) are gone; `builds.rs` keeps `BUILDER`/`ensure_builder`/`builder`/`failure` only (history enumeration for the Builds view was window-only).
- **`parse_ipam` test-only (CTRS-07):** restored as `#[cfg(test)] fn` in `network.rs` after the pin's known-red dead-code warning was deleted; the suite keeps its upstream IPAM parsing coverage with zero warnings.
- **Deletions keep the gauntlet green (CTRS-07):** `cargo check --workspace` 0 warnings (the pin had 1, now fixed in its own edit); `cargo test --workspace` 193 pass (359 at the pin; delta = deleted subsystems' tests); `conformance/smoke.sh` 15/15; `cargo tree --locked --target all` and the lockfile scan show no gtk/webkit/javascriptcore/glib/app-kit/core-text/share packages; `cargo audit` clean (exit 0).
- **`scripts/ci/linux-packages.sh`, `linux-build.sh`, `notices.sh`, `test-version.sh` deleted (CTRS-07):** they referenced the deleted `packaging/` tree and `about.hbs`, or the deleted updater/release feed. `guest-cache.sh`, `kernel-source.sh` (GPL source offer) remain.
