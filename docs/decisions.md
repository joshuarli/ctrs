- **CTRS-14 HTTP/1.1 conformance oracle (`conformance/http.sh` + `conformance/http/*.py`):** 10 fixtures against a live scratch daemon (garbage-in/4xx, `Expect: 100-continue`, chunked with trailers incl. chunk extensions, keep-alive + pipelining, slow headers byte-by-byte, framing rejection: mismatched/non-numeric repeated `Content-Length` and CL+TE, identical repeated CL accepted, 9 MiB streaming through `/images/load`, 64 KiB head cap, cancellation, corrupted-framing negative control). All pass with the fix. The `corrupted-framing` fixture is a weak discriminator on its own (the old parser also refused those byte sequences); the other three carry the #134 signal.
- **#134 fixes in `http.rs` (CTRS-14; the handwritten parser, not a replacement):** (1) interim `100 Continue` written before the body is read, on both buffered and streamed paths — `read_request` now takes the writer; `api.rs` serves with it and maps framing errors to `400 bad request framing` then close instead of dropping silently; (2) chunked decoder shared by buffered and streamed paths: chunk-size lines bounded (64), chunk CRLF verified, trailer section consumed (bounded: 8 KiB/line, 32 fields) after the zero-size chunk — trailer bytes can no longer leak into the next request on a keep-alive connection; (3) framing validation before dispatch: `Content-Length` + `Transfer-Encoding` rejected (accepting identical repeated CL per RFC 7230, which ctrs already did, and rejecting CL+TE per the #134 disposition, stricter than Docker), non-numeric/mismatched repeated CL rejected — the old code silently treated an unparsable CL as no body; (4) the buffered path no longer acknowledges a body it never reads: fixed-length body read errors surface as 400, and `read_exact` EOF closes instead of hanging.
- **`Next::Close` may leave a body unread (`http.rs`, unchanged in CTRS-14):** `/images/load` whose archive ends early (tar stops at the zero-block end-of-archive while a padded body still has bytes in flight) answers and closes with the client's tail unsent — the client sees RST/EPIPE, which is legal HTTP (`Connection: close`) but noteworthy for clients that push more bytes than the archive needs. Left as is: draining arbitrary bodies in the close path risks indefinite block without a timeout, and the oracle stages exactly-sized bodies, so the fixture exercises the clean FIN path. Flagged for CTRS-15/20 rather than fixed here.
- **Fixture staging lesson (CTRS-14):** a 9 MiB body built by *padding* a real image tar with trailing zeros made `tar` stop at end-of-archive early, leaving bytes unread and producing RST — the fixture now builds its own one-layer `ctrs14-http:latest` image inline (classic `manifest.json` layout, supported by `archive::load`), fully offline, no network, no runner-staged files. Also learned: the interim `100 Continue` response keeps its own terminating blank line; byte-level clients must consume it (two fixture bugs).
