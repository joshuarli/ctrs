**Verified dominant work:** application/database CPU. The frozen fixture
`bench/native/fixtures/w1/api/app.py` supplies synchronous threadpool endpoints
sharing one psycopg connection; `_db()` additionally executes SELECT1 per request.
Large voluntary switches/futex waits are consistent with application handoff and
connection serialization, not runnable CPU starvation. Perf/schedstat and small
runqueue waits do not establish an engine scheduler deficit. This identifies the
dominant boundary, **not a confirmed explanation of a stable ctrs/Docker gap**.

**Forwarding:** measurable loopback cost, but bypass does not consistently remove
the timing difference. The controls explicitly disprove treating relay presence
alone as the settled historical cause.

**Storage:** cgroup IO/PSI show writes and sub-second some-pressure in these normal
controls. Task delay accounting is disabled, so zero blkio_delay is not evidence
of zero storage wait. Fdatasync/off-CPU syscall distributions are retained; these
do not assign individual p99 outliers to storage. Strace inflated completion to
roughly 190-208 seconds and must not be used as ordinary performance evidence.

## Hypotheses and predeclared cohorts

H1, declared before editing: balanced x86_64 seccomp denial dispatch instead of
the linear deny chain, preserving policy and ARM64 behavior. Reachability to
installation is established by the child-exec path and live agent identities;
per-call BPF execution on always-allowed calls is **unverified** because this
kernel contains the seccomp allow cache. This was documented before the cohort,
not promoted to a confirmed hotspot from syscall counts. Kernel cache debug is
disabled. Differential/empty/common-call tests cover the filter policy.

H2, declared after reverting H1 and before editing: protocol-independent 8KiB
read/write exchanges before switching permanently to existing splice on a full
read, to reduce the verified small-message relay component. No claimed fix to the
dominant frozen application's shared-connection work. Empty/small/bulk/error tests
and existing port/network cases cover transport semantics.

Each experiment separately predeclared ten three-way rounds: even B,C,D; odd
D,C,B. B=baseline ctrs, C=candidate ctrs, D=frozen Docker. Thirty trials each,
same work/seeds/periodic sampler and allowed CPUs. Primary p99 paired-median ratio
must have bootstrap 95% upper<=0.95; completion guardrail upper<=1.03; ten complete
correct/resource-valid B/C pairs required. Bootstrap uses the existing reporting
implementation (2,000 resamples, fixed seed). No count reduction, speed exclusion,
replacement trial or pooling between experiments.

H1's controller stopped twice on pretrial live-agent assertions: info() does not
boot the lazy agent; later the agent intentionally slept after 60 idle seconds
between two Docker trials (journal retained). Four completed trials were kept;
the remaining 26 continued in exact declared order under a separate native run ID.
Untimed owned Python-pass warmup wakes an absent agent before requiring live
host/agent hashes. This is a disclosed controller/protocol interruption, not an
uninterrupted qualification run. H2 used the corrected controller throughout.
