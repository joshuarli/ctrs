# Connection lifecycle fixture

The host runs concurrent clients against the pinned API image through a loopback published port. Newline-delimited JSON responses contain deterministic request and chunk identities and are checked exactly. Each mode and its parameters define a separate cohort. Streaming lateness is measured against the client send schedule, so includes transport and server scheduling. Cancellation closes after one chunk; cleanup latency runs from completion of all client workers until the server reports zero open sessions. Restart timing starts immediately before the restart command; retries begin after the command returns, so earlier availability is not observed. Errors during reconnect remain visible and make correctness fail, even if a later retry succeeds. Idle durations above 300 seconds expose the host relay's socket timeout.
